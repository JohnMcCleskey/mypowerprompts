# Tools

Use tools to verify capabilities, compare releases, and gather supporting evidence.

## Approved Tool List
- Check primary sources, release notes, docs, changelogs, and product updates.
- Compare competing capabilities when evaluating adoption.
- Capture exact dates, versions, and constraints when relevance is time-sensitive.

## Tool Selection Rules
- Use the most authoritative source available.
- Prefer a fresh source over a broad source when the capability is changing quickly.
- Use tools to verify portability claims before recommending them.

## Prohibited Actions
- Do not present unverified capabilities as production-ready.
- Do not imply support for a platform feature that is not documented.
- Do not blend provider-specific behavior into a supposedly portable recommendation.

## Approval Gates
- Ask for confirmation before recommending a pilot, migration, or major adoption change.
- Pause when a capability is experimental or access-limited.

## Data Handling Cautions
- Treat source links, release notes, and vendor comparisons as part of the audit trail.
- Preserve freshness dates and avoid carrying stale claims forward.
