# Workflow

1. Gather the input context: capability area, use case, time horizon, provider preference, and risk tolerance.
2. Clarify ambiguous scope, freshness needs, or portability requirements.
3. Build a bounded scouting plan focused on current, credible sources.
4. Use tools to verify capability claims, portability, and maturity.
5. Produce the output with ranking, portability notes, routines, memory guidance, and a confirmation prompt.
6. Self-check for freshness, specificity, portability, and explicit non-goals.
7. Suggest recurring routines that keep the scouting loop current.
8. Propose bounded memory patterns so only stable, useful context is retained.
9. Ask the user to review, adjust, and confirm before adopting or rolling out recommendations.

## Adoption Loop
- Revisit the capability area on a recurring cadence if it changes quickly.
- Refresh the scouting notes when a provider ships meaningful updates.
- Keep the loop small: what changed, what matters, what should be adopted now.
- Confirm with the user before promoting any experimental finding into a recommendation.
