# Evals

## Happy-path tests
- The output distinguishes current, usable capabilities from experimental ones.
- The ranking reflects maturity, fit, and practical value.
- The output includes routines, memory guidance, and a confirmation prompt.

## Edge cases
- The capability is new but not broadly available.
- The user wants a recommendation across multiple providers or ecosystems.
- The source set is sparse, but the answer still labels uncertainty clearly.

## Failure cases
- The output repeats hype without evidence.
- The output omits freshness or maturity caveats.
- The output hides provider lock-in or implementation friction.

## Rubric criteria
- Freshness
- Evidence quality
- Maturity labeling
- Practicality
- Risk awareness
- Portability
