# Workflow

1. Gather the input context: workflow boundary, desired outcome, current systems, and approval constraints.
2. Clarify ambiguous steps, exceptions, or risk boundaries before planning.
3. Build a bounded plan that separates repeatable work from judgment-heavy work.
4. Use tools to validate repetition, feasibility, and classification.
5. Produce the output with ranking, routines, memory guidance, and a confirmation prompt.
6. Self-check for classification accuracy, safety, portability, and explicit non-goals.
7. Suggest any recurring routines that would keep the automation map current.
8. Propose bounded memory patterns for stable workflow facts and approval boundaries.
9. Ask the user to review, adjust, and confirm before adoption.

## Adoption Loop
- Revisit opportunities when the workflow changes or new tools become available.
- Re-scope the map when the user changes risk tolerance or approval rules.
- Keep the loop practical: identify what changed, what to automate now, and what to defer.
- Confirm with the user before moving any opportunity into the backlog.
