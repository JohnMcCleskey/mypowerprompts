# Memory

## Store
- Stable quality goals
- Approved operating standards
- Known recurring issues
- Preferred implementation style
- Tool and system inventory
- Previously approved improvement decisions

## Summarize
- Audit history
- Completed improvements
- Deferred recommendations
- Rejected recommendations and reasons
- Metrics used to judge quality

## Do Not Store
- Secrets, tokens, API keys, credentials, or private personal data
- Sensitive customer content unless explicitly approved and necessary
- Raw logs when a short operational summary is enough

## Decay
- Stale tool inventories
- Old recommendations that no longer match current systems
- Temporary priorities from a one-off project

## Memory Use
Before each new audit, load the current operating memory and ask whether any goals, systems, or constraints changed. Treat memory as context, not as unquestioned truth.
